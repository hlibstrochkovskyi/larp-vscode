# LARP for Visual Studio Code

Official VS Code language support for [LARP](https://github.com/hlibstrochkovskyi/larp-lang),
compatible with compiler **v0.1.0-preview.1**. Requires VS Code **1.85 or newer**.

Open a `.larp` file to enable syntax highlighting, bracket matching, automatic
bracket/quote closing, indentation, comment commands, and snippets. The extension
is declarative: it does not require a compiler installation or execute code.

## Install locally

Download or build `larp-vscode-0.1.0.vsix`, then run:

```sh
code --install-extension ./dist/larp-vscode-0.1.0.vsix
```

Alternatively, open Extensions in VS Code, choose **… → Install from VSIX…**, and
select the file. Reopen your `.larp` file or run **Developer: Reload Window** if
needed. The language indicator in the status bar should show **LARP**.

To remove it:

```sh
code --uninstall-extension hlibstrochkovskyi.larp-vscode
```

## Features

- TextMate highlighting for reserved words, declarations, objects, roles,
  extensions, function types, lambdas, nested generic types, effect bounds,
  scenarios, built-in functions, decimal numbers, strings, and comments.
- Correct distinction between `0..10`, floating-point numbers, and unary signs.
- Unicode string contents; the five supported escapes; non-nesting block comments.
- Bracket matching for `{}`, `[]`, and `()`. String quotes also close automatically.
- Indentation for blocks and multiline calls/arrays. Uses your editor's tab settings.
- **Toggle Line Comment** and **Toggle Block Comment** use `//` and `/* … */`.
- Works with untrusted and virtual workspaces; no runtime dependencies or telemetry.

Highlight colors come from your selected theme. TextMate highlighting cannot
resolve shadowed prelude names, infer receiver types, or validate programs.
Type and symbol coloring is a syntactic approximation, particularly when comments
or newlines split a declaration. Use the LARP compiler for diagnostics. This
version provides no LSP, semantic tokens, formatter, compiler runner, or debugger.

## Snippets

Type a prefix and select its completion, or use **Insert Snippet** in the command
palette. Tab moves through placeholders.

| Prefix | Expansion |
| --- | --- |
| `main` | `main_character` entry block |
| `sidequest` | Function declaration |
| `let`, `var` | Inferred or explicitly typed binding |
| `if`, `ifelse` | Conditional blocks |
| `npc`, `locked_in`, `goon` | Range, while, and infinite loops |
| `yap` | Observation call |
| `archetype`, `role` | Class or role declaration |
| `larp`, `flex`, `canon` | Scenario, claim, and field selection |
| `nonchalant`, `sybau` | Memoized binding and observation suppression |
| `lambda` | Lambda with a typed parameter |

`larp`, `flex`, and `canon` require an existing scenario-eligible root; edit their
placeholders to match your program. A `sidequest` returning a non-`unit` type
needs an appropriate return statement.

## Development and tests

Use Node.js **22.14+** (24 LTS recommended), npm, and Python **3.11+** for package
verification. No TypeScript compilation is needed.

```sh
npm ci
npm test
npm run package
```

The package appears in `dist/` with a SHA-256 checksum. Packaging runs the tests
and uses Microsoft's `@vscode/vsce`; only the manifest, grammar, language
configuration, snippets, README, changelog, and MIT license enter the VSIX.
These commands do not publish the extension.

`npm test` runs real TextMate/Oniguruma scope assertions, editor configuration
checks, and all **102 pinned upstream source fixtures**, comparing token scopes
against **6614 spans generated by the upstream Rust lexer**. Semantic-error and
runtime-error fixtures are included because their source still needs highlighting.
The compiler and language repository are not needed for this test suite.

For an Extension Development Host, open this repository in VS Code and press
**F5**. It opens the official pitch-deck example. Run **Developer: Inspect Editor
Tokens and Scopes** to inspect `source.larp` and individual token scopes.

```sh
npm run test:editor
# Linux without a desktop session:
xvfb-run -a npm run test:editor
# Use a particular installed VS Code binary instead of downloading one:
VSCODE_EXECUTABLE=/usr/share/code/code npm run test:editor
```

Editor tests use a separate profile/workspace and verify file detection, automatic
bracket closing, indentation, comment commands, and snippet expansion. The default
test runner downloads a stable VS Code; set `VSCODE_VERSION=1.85.2` to check the
minimum supported series. A desktop session or Xvfb and permission to launch
Electron are required. [Validation details](docs/validation.md) distinguish executed
checks from environment-limited checks.

To check default snippet expansions and all official examples with the compiler:

```sh
LARP_CLI=/absolute/path/to/larp npm run test:compiler
```

To regenerate the lexer oracle after reviewing an upstream change, use Rust and
a checkout matching the pinned baseline:

```sh
python3 scripts/update-lexer-oracle.py --upstream /absolute/path/to/larp-lang
npm test
```

The generator reads upstream sources and builds a tiny lexer driver in a temporary
directory. It checks the lexer's Git blob hash before generating expectations.
See [syntax sources and decisions](docs/syntax-sources.md).
